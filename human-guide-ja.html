Agent Workflow Starter
はじめるワークフローファイルツール例English

AIエージェントを安全に使って仕事を進める

Claude Code などのファイル編集AIを使い、文章、調査、教材、ドキュメント、スクリプト、小規模プロジェクトを、確認可能でレビューしやすい形にするための実践ガイドです。

はじめるGitHubを開く

Start

まずリポジトリから始める

リポジトリを clone または fork してローカルで開き、AIには最初から範囲を限定した1つのタスクを渡します。

git clone https://github.com/logohere/agent-workflow-starter.git
cd agent-workflow-starter

1. ゴールを明確にする

成果物、対象者、範囲、やらないこと、完了条件を指定します。

2. 必要なファイルだけ読む

タスクに必要なファイルだけを確認させます。

3. 計画を書かせる

変更ファイル、手順、チェック、今回やらない事項を列挙させます。

4. 計画を疑う

抜け、危険、範囲の広さ、承認が必要な点を確認します。

5. 小さく変更する

関係ない改善を混ぜず、必要な変更だけを行います。

6. 引き継ぎを残す

変更内容、通ったチェック、残作業を記録します。

Core rule

ゴールをAIに任せない

AIは下書き、検索、比較、整理、スクリプト作成、チェックに向いています。一方で、目的、判断基準、品質基準、承認、最終レビューは人間が持ちます。

レビュー可能な仕事にする

計画、小さな変更、チェック、引き継ぎを使います。「全体を改善して」のような広すぎる依頼は避けます。

Bounded task

AIに明確なターゲットを渡す

[対象者] 向けに [成果物] を作成または更新してください。
[ファイル] を資料として使ってください。
範囲は [スコープ] に限定してください。
[やらないこと] は変更しないでください。
編集前に実装計画を書いてください。
編集後にチェックを実行し、差分を要約してください。

Plan review

実行前に計画を検証する

何が抜けている？
何が壊れる可能性がある？
どの前提が間違っている可能性がある？
範囲が広すぎる部分は？
他の作業に依存している部分は？
今回は延期すべきものは？
承認が必要なものは？
最小の有用な変更は何？

Context

トークンは証拠に使う

全ファイルを貼り付ける代わりに先に検索し、必要な箇所だけ読みます。
長いチャットで議論し続ける代わりに引き継ぎを書き、ファイルから新しいセッションを始めます。
全面リライトを頼む代わりに差分と各変更の理由を求めます。
同じ検索を繰り返す代わりにローカルSQLite検索や小さなスクリプトを使います。

Restart

会話が間違った方向に進んだらやり直す

誤った前提が繰り返される停止し、正しい現在状態を引き継ぎに書きます。
AIが確認前に編集する停止し、プロジェクト、Issue、PR、関連ファイルから再開します。
タスクの方向が変わった古い決定を破棄済みとして記録し、新しいゴールを明示します。
複数の計画が混ざった1つだけ選び、残りはフォローアップに回します。

Search

検索方法を先に選ぶ

Exact lookupファイル名、見出し、コマンド、ID、正確な語句が分かる場合。
Keyword / FTS5ファイル内で使われていそうな単語が分かる場合。
Fuzzy searchタイプミス、部分一致、表記揺れを想定する場合。
Semantic search概念は分かるが表現が分からない場合。通常は埋め込みとベクトル検索が必要。
Hybrid searchキーワード精度と意味検索の再現率を両方使う場合。
